# RAG 语义证据验证与局部回答设计

## 目标

把“检索结果相关”与“证据足以直接回答”分离。系统应将复合问题拆成最多 5 个原子子问题，只回答有直接证据且通过生成后校验的部分；没有证据或无法验证的部分必须明确局部拒答。

## 当前问题

当前 `Retriever` 只要找到超过相似度阈值的文本块，就把 `has_sufficient_evidence` 设为真。`CustomerServiceAgent` 的 `judge` 节点只读取该布尔值，没有执行语义判断。因此，询问产品价格时，即使候选资料只介绍功能，仍会进入生成节点；最终是否拒答依赖生成模型自行约束，行为不稳定。

## 已确认决策

- 问题改写与原子子问题拆分合并为一次结构化模型调用。
- 最多处理 5 个原子子问题；超出时只保留前 5 个，并在回答中说明范围限制。
- 拆分结果无法解析时，把改写前的当前问题作为单个子问题继续处理。
- 每个子问题独立执行向量检索，最多取 7 条候选。
- 候选相似度阈值固定为 `0.5`；该阈值只决定候选是否进入语义判定，不代表证据充分。
- 语义判定一次处理全部子问题，逐项返回 `answerable`、直接证据编号、缺失信息和简短原因。
- 语义判定输出无法解析或引用不存在的证据时，对受影响子问题保守拒答。
- 只把可回答子问题及其直接证据交给生成模型；不可回答子问题由程序生成固定局部拒答。
- 生成正文在服务端缓冲，校验完成前不能把正文增量发送给用户。
- 生成后逐项执行语义支持校验，同时由程序校验引用编号和数字事实。
- 明确校验失败时允许携带失败原因重新生成一次；第二次仍失败则只降级对应子问题。
- 校验输出无法解析时不重试，直接对受影响子问题保守拒答。
- 最终回答按原子子问题分段，保留已验证回答，并明确标出缺少证据的部分。
- 候选资料继续显示在证据面板；直接支持答案的资料标记为“回答证据”，其余标记为“相关资料，不足以直接回答”。
- 第一版继续使用当前千问聊天模型，温度为 0，不增加第二个模型。

## 数据流

```text
当前问题 + 会话历史
        ↓
结构化改写与拆分（最多 5 项）
        ↓
每项独立向量检索（Top 7，相似度 >= 0.5）
        ↓
一次语义证据判定（逐项选择直接证据）
        ↓
回答计划
├─ 可回答项：进入生成
└─ 不可回答项：固定局部拒答
        ↓
服务端缓冲生成正文
        ↓
逐项语义校验 + 引用/数字确定性校验
├─ 通过：保留
├─ 明确失败：重生成一次后再校验
└─ 解析失败或二次失败：局部拒答
        ↓
合并分段回答并发送给前端
```

## 领域模型

- `SubQuestion`：稳定 ID、原子问题文本。
- `EvidenceDecision`：子问题 ID、是否可回答、直接证据编号、缺失信息、原因。
- `AnswerPart`：子问题 ID、问题、正文、引用编号、是否已验证、拒答原因。
- `Evidence.support_status`：`supporting` 或 `related`，用于区分回答证据与仅相关候选。
- `Evidence.subquestion_id` 与 `Evidence.subquestion`：记录候选来自哪个原子子问题。

所有模型都只包含可安全发送到前端的数据，不包含提示词、API Key、本地路径或内容哈希。

## 结构化模型边界

### 改写与拆分

模型必须返回 JSON 对象，包含独立问题和子问题数组。子问题 ID 由程序重新编号为 `q1` 至 `q5`，不信任模型提供的 ID。空列表或非法 JSON 回退为单个原问题。

### 证据判定

模型看到每个子问题及其编号候选，返回逐项判定。程序只接受当前子问题实际拥有的证据编号；越权引用、遗漏判定或非法 JSON均视为该项不可回答。

### 生成与校验

生成模型只接收可回答项和各自允许的证据。回答必须为 JSON，并逐项给出正文。校验模型判断每项结论是否完全由允许证据支持。程序还必须确认：

- 至少存在一个引用；
- 所有引用都属于该子问题允许的直接证据；
- 去除引用编号后，回答中的阿拉伯数字都能在允许证据原文中找到。

## 前端行为

- 校验完成前只展示阶段状态，不展示未验证正文。
- 执行过程至少显示：问题拆分、逐项检索、语义判定、答案生成、答案校验、必要时重新生成。
- 最终状态只在全部子项完成后更新。
- 全部子项拒答时显示“证据不足 · 已拒答”；至少一项通过时显示“回答完成”，正文内部逐项标识不可回答部分。
- 证据面板同时显示回答证据和相关候选，并使用不同标签。

## 失败与安全策略

- 任一外部模型调用异常继续转换为安全错误事件，不暴露底层异常、提示词或密钥。
- 拆分失败回退为单问题；判定和校验失败采用 fail-closed。
- 未验证正文不能进入 SSE `answer_delta`，也不能写入会话历史。
- 重新生成最多一次，不建立循环。

## 验收标准

- “价格 + 是否支持 Wi-Fi 6”且资料只有 Wi-Fi 6 时，只回答 Wi-Fi 6，价格局部拒答。
- 5 条高相似功能资料但没有价格时，在生成前把价格判为不可回答。
- 每个子问题检索参数为 Top 7、阈值 0.5。
- 多于 5 个子问题时只处理前 5 个并提示范围限制。
- 拆分非法 JSON 时按单问题继续。
- 判定非法 JSON、越权证据编号或缺失判定时局部拒答。
- 生成内容引用不存在的编号或新增证据中没有的数字时，触发一次重生成。
- 第二次生成仍不合格时只拒答失败项，其他已验证回答保留。
- 校验完成前 SSE 中不存在回答正文。
- 前端能区分“回答证据”和“相关资料，不足以直接回答”。
