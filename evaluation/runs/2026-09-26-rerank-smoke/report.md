# qwen3-rerank 接入与验证报告

日期：2026-09-26。范围：新增重排与必要的网页显示；未修改聊天模型、Embedding、切块、语义判定和生成后校验逻辑。未重新运行完整 100 题评测。

## 实施结果

- 聊天模型仍为 `qwen3.7-plus`，Embedding 仍为 `text-embedding-v4`，现有 API Key 已通过真实重排调用验证。
- 生产链路：问题改写/拆分 → 向量召回 → `qwen3-rerank` → 每个子问题 Top 7 → 原有语义证据判定 → 回答/局部拒答 → 原有生成后校验。
- 保留既有宽召回规模 `retrieval_top_k × 20`，当前为请求最多 140 条，所选现有知识库实际共 55 个 chunk。没有重新上传、切块或向量化。
- 重排输入包含文件名、标题路径和片段正文，以返回的原始索引匹配回原片段；文档 ID、chunk_index、正文和引用对应关系保持一致。
- 生产重排链路不再使用旧向量相似度 0.5 提前过滤，也不把该阈值套用到重排分数。重排只负责相关性排序，不代表资料足以回答问题。
- `similarity` 仍表示原向量分数，新增 `rerank_score` 独立记录。网页显示 Top 7，并区分重排与向量分数。
- HTTP 错误、网络失败和非法返回明确报错；不降级为旧排序，不在失败后继续生成答案。单次 HTTP 超时配置 30 秒，无重排自动重试。
- 未注入重排器的旧 `Retriever` 调用保留原契约与原测试；生产 `build_container` 始终注入重排器，不存在故障时偷偷切换回旧逻辑。

## 接口及配置

默认模型固定为 `qwen3-rerank`，默认完整接口：

```text
https://maas.qianwenaiapi.com/compatible-api/v1/reranks
```

直接复用 `QWEN_API_KEY`。新增可覆盖配置 `QWEN_RERANK_URL`，已写入 `.env.example`；现有 `.env` 不需要增加此变量，省略时使用上述地址。聊天/Embedding 的 `QWEN_BASE_URL` 没有修改。

请求为顶层 `model/query/documents/top_n`；使用官方默认的问答检索排序指令。参考：[千问官方重排接口](https://platform.qianwenai.com/docs/api-reference/rerank/openai-rerank)。

## 真实调用结果与证据边界

从冻结 100 题中选择三条历史代表用例，使用现有系统生产装配和实际模型调用，串行执行。原始数据集、知识库和旧基线结果未改动。运行前沿用评测工具的 live corpus 校验。

| 用例 | 首次执行 | 独立复测 | 核心行为 |
| --- | --- | --- | --- |
| RAG-038：USB 口能接打印机吗？ | 完成，32.390 秒 | 未重试 | 明确不能，说明仅支持存储共享，并给出电脑/打印服务器替代方式 |
| RAG-054：AX6000 的尺寸是多少？ | 重排网络连接/超时错误，32.483 秒 | 完成，48.932 秒 | 回答含天线、约长 250 毫米、宽 150 毫米、高 200 毫米 |
| RAG-056：价格和尺寸如何？ | 重排网络连接/超时错误，31.032 秒 | 完成，41.130 秒 | 价格拒答，尺寸正确回答，引用匹配 |

首次执行成功 1/3，网络类失败 2/3；仅对失败两题各手动复测一次，复测成功 2/2。随后成功记录的标注检索命中与证据组覆盖均为 3/3。**这不是首次执行 100% 成功，也不是完整评测准确率；未对三题重新执行五维 1–5 分评分。**

关键实例：RAG-038 命中的直接 FAQ 为 `2a101509-5c7a-432b-b385-93bc3091be9c:15`。旧向量分数约 `0.4716`，会被旧 0.5 门槛剔除；本次重排分数约 `0.8977`，排第 1，并支持了正确回答。

RAG-056 的价格候选即使被返回，语义判定仍为不可回答；尺寸片段可回答，最终引用为 `[8]`，体现跨子问题重新编号后的对应关系。
